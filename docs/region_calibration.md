# 本地预览区域标定

正常启动 `realtime_web.py` 或双击 `open_preview.bat`。若旧进程仍在运行，需要先重启预览服务以加载新代码，然后刷新 `http://127.0.0.1:8000/`。

主端口（默认 8000）用于页面和标定接口；视频从后续端口（8001、8002…，每 6 路一组）加载，避免视频长连接占满标定页的浏览器连接。更新旧版本后，也请刷新已打开的监控网格页。

多路预览的 JPEG 最大宽度为 960，保持原宽高比；检测输入、标定冻结底图及坐标不受预览缩图影响。编码繁忙时只保留最新待显示帧。PyAV 的连接及读取超时均为 8 秒，超时后进入重连流程。

车辆框线按源图宽度放大，在 960 宽预览中保留约 2.5px 线宽；类别和置信度标签保留实心底色，字号较首版加粗样式缩小一档，减少遮挡。

使用 PyAV 后端及 CUDA 检测设备时，自动启用 CUDA/NVDEC 视频解码，逐路连接日志会显示实际采用的解码器；不支持硬解的编码仍可使用 CPU。`--device cpu` 保持 CPU 解码。2026-11-10 在 RTX 5060 上验证十路同时出图，视频解码单元采样占用约 4–6%，整卡显存约 6.4/8 GB。十路检测后的预览通常仍约 8 FPS，不能把硬解提速等同于检测帧率同比提高。

若原始 RTSP 本身停帧，预览优化无法补回缺失画面。2026-11-10 对 2763 的一次 30 秒源流实测约 5.4 FPS、最长到帧间隔 2.09 秒；此前录片存在最长 15.27 秒的时间戳缺口。计数脚本遇到超过 0.5 秒的时间戳缺口会重置跟踪，避免跨缺口误计，但缺口期间可能漏计；应先恢复源流连续性，再核验计数准确率。

后续直接使用 RTSP/TCP 读取 RTP（绕过 FFmpeg、解码和检测）对照：2763 约 6.57 FPS、最长到帧间隔 2.219 秒，RTP 视频时间戳最大前跳 6.764 秒；同服务器的对照路约 23.01 FPS、最长到帧间隔 0.328 秒、时间戳最大步长 0.082 秒。两路均未发现 RTP 序号缺口或乱序。时间戳前跳不等于实际传输停顿相同秒数；这次采样确认异常已出现在本机接收的原始流中，但无法仅凭客户端区分摄像头、上传链路或网关上游取流。网关状态接口未能访问，项目中缺少 ICC 访问配置，尚未修改上游设置。

本次原始包到达时间、RTP 帧时钟及 CPU/GPU 解码对照分别保存在本地 `temp/traffic_2763_gpu_20261110_b/` 和 `temp/traffic_2763_gpu_20261110_rtp/`；可用 `temp/source_packet_probe.py`、`temp/rtp_clock_probe.py` 复测，输出目录须选择新目录。

1. 在目标摄像头标题旁点击“区域标定”，新标签页会冻结该路实际推理画面的原始截图。
2. 沿目标道路边界依次点击；至少 3 个点后点击起点或“完成区域”闭合 ROI。
3. 点击两个端点画有限计数线。整段必须位于 ROI 内。
4. 依次点击来车侧、驶离侧，画方向箭头；方向不能与计数线平行。
5. 点击“保存标定”，返回预览即可看到 ROI、计数线和箭头。也可只画 ROI 后直接保存。

选择绘制工具后点击画面可重画对应图形。“撤销”或 Ctrl/⌘+Z 可撤回操作；“清空重画”可撤销，只有保存后才会移除旧标定。“刷新底图”获取新的冻结画面。关闭有未保存修改的页面时浏览器会提示。

配置保存在脚本旁的 `camera_regions.json`，按视频源和 `--crop` 配置隔离，摄像头列表重排不会串用。多个预览进程保存时会合并最新配置并串行写入，避免互相覆盖。配置及锁文件均由仓库忽略规则排除。归一化坐标支持相同视角、相同宽高比的分辨率变化；宽高比变化会停用旧叠加并提示重画。转向、变焦或画面布局变化后也需要重新标定。

实时服务已接入逐路车辆跟踪和过线类别事件 API，完整标定保存后自动参与计数。ROI 判断、类别融合和接口调用方式见 [车辆事件 API](traffic_api.md)。
