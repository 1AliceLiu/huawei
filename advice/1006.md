## 1. 问题：background 误分类占比大

要分清两个方向——它们的病因和解法完全不同：

**(A) 真目标被漏成 background（FN）**：Motorcycle 22%、Coach/面包车类 8~9%。
- 病因：小目标 / 夜间低对比 / 遮挡截断；模型 objectness 不足；640 分辨率下小目标特征被下采样吃掉；训练/分配阈值（TAL）对小目标偏严。
- 建议：
  1. **提高输入分辨率**：640 → 960/1280（评估也同步），对 Motorcycle/Container 这类小目标收益最直接。
  2. **加 P2 小目标检测头**：在 backbone 浅层加高分辨率 P2 分支，或改用对小目标更友好的 neck。
  3. **小目标增强**：mosaic + scale + copy-paste 小目标实例，提高小实例在 batch 中的出现频率。
  4. **降低漏检**：适当调低训练/推理 conf，或对稀有类用 per-class 阈值；配合 TAL 的 `topk`/`alpha` 放宽小目标分配。
  5. **核查标注**：用现模型在 train 集推理，找"模型预测有框但 GT 没有"的图（漏标），未标注的目标会同时抬高 FP、压低 AP。可复用 `scripts/audit_ambiguous.py`。

**(B) 真 background 被判成目标（FP）**：Private Car 37%、MGV 14%。
- 病因：Private Car/MGV 框数占绝对多数（训练里 Private Car ≈40%），背景难负样本不足；路牌、车灯、反光、文字被当作车；过曝/夜间。
- 建议：
  1. **难负样本挖掘**：收集 FP 截图（空路面、广告牌、反光、堵车重影）加入负样本/背景。仓库已有 `scripts/mine_pseudo.py`、`scripts/audit_car_fp.py` 可作为起点。
  2. **过采样空镜/纯背景**：RTSP 空镜入库（仓库 `scripts/collect_data.py`）。
  3. **类别再平衡**：对高频类（Private Car）用 focal loss / class weight，或在损失中对负样本采样，压制其过强先验。
  4. **后处理**：对 Private Car/MGV 单独提高 conf 阈值，抑制 FP（会牺牲少量召回，需在 PR 曲线上取折中）。
  5. **确认标签完整性**：漏标车辆=把"目标"当背景训，会系统性损害两类。优先做标注复核。

## 2. 问题：LGV ↔ MGV 互相误识别（LGV AP 0.648、MGV AP 0.741）

根因是**视觉不可分**：载重/吨位在监控视角、640 分辨率下没有可判读特征（README 记录旧版就是 37% LGV→MGV / 17% HGV→MGV，正因如此才做过 v10 merge8 合并为 Truck）。这是数据本身的边界问题，不是单纯调参能解决。

两条路线，按业务取舍：

**路线 A（省力、见效最快）：合并 LGV/MGV/HGV → Truck**
- 直接把最差的三个类合并，消除不可分边界，整体 mAP50 会有可观提升。仓库已有成熟脚本 `scripts/remap_batch12_merge8.py` 和 v10 的经验。
- 代价：丢失吨位细分。若业务只需要"货车"这一粒度，这是最优解。

**路线 B（必须区分时）：给模型更多可判读的信息**
1. **两阶段：检测 + 裁剪二次分类**。先检测出 Truck 框，把原图 crop 放大后送入分类头（或尺寸/长宽比特征）做 HGV/MGV/LGV 三分类；crop 能显著提高有效分辨率。
2. **提高分辨率**：960/1280 训练，让轴数、货箱、车牌尺寸等线索保留。
3. **尺寸先验**：HGV/MGV/LGV 的框尺寸分布不同，可在回归分支或分类 logit 上融入框尺寸/长宽比（size-aware）。
4. **标注规范统一**：明确按什么标准分（轴数？总重？车身长度？）。若标注员各自凭感觉，模型学到的就是噪声——这是 AP 上不去的隐藏原因。
5. **补充边界样本**：同车型不同载重/不同车架长度的成对样本。

## 3. 问题：Motorcycle 样本不足 + 人工把"人"标成 motorcycle

这是**优先级最高**的问题，因为**错误标签比少量标签危害更大**：把行人标成 motorcycle 会让模型学到"人=摩托车"，既毁 Motorcycle 的精度，也会污染 background 与相邻类。

**先清洗，再增数据：**
1. **标注审计**：对 train 中所有 motorcycle 标注做 crop + 人工复核，剔除非摩托车的实例（行人、单车、骑手以外的部分）。可写脚本批量导出 motorcycle 框 crop；`scripts/audit_ambiguous.py` 思路可复用。
2. **明确标注 SOP**：
   - 什么算 motorcycle（是否含自行车/电动车）？
   - **骑手怎么标**？设定统一规则（只框车体，或统一框"车+人"），不要一人一标准。
   - 对不确定/遮挡实例设"忽略"策略（不要随手标成某类）。
3. **如果关心行人**：加独立 `Person` 类，而不是塞进 motorcycle；若不关心，纯人框应删除或标记为背景。
4. **补样本（在标签干净之后）**：定向采集摩托车场景（不同角度/夜间），copy-paste + mosaic 过采样；但**增强无法修复错误标签**。
5. **评估谨慎**：motorcycle 在 frozen val 只有几十个框，AP 方差很大，单次结果不可靠；应多次运行/交叉验证看均值。

## 4. 问题：Van 易误识别为 Private Car（Van AP 0.722、26% 被判成 Private Car）

Van 与 Private Car 常同底盘，低分辨率下差异只剩车顶/车窗比例、货箱、涂装、车顶架。README 也记录过 27% Van→Private Car。

建议：
1. **提高分辨率 + crop 二次分类**：对 car 类框 crop 放大，区分 Van / Private Car 会容易很多（同 §2 路线 B）。
2. **针对性数据**：补充 Van 与 Private Car 的成对易混样本；对 Van 过采样/copy-paste，提升其在 batch 中的占比（Van 训练框数远少于 Private Car）。
3. **类别边界复核**：确认业务上 Van（轻型客货车）与 Private Car 的定义边界；对"改装后已无法区分"的实例，合并或重定义，别让标注员硬分。
4. **损失加权**：给 Van 更高 cls 权重或过采样，缓解 Private Car 先验过强。
5. **注意力/线索增强**：在 backbone 末端加坐标注意力（Coordinate Attention）等，聚焦车顶/车窗/货箱区域。
6. **后处理**：Van 是业务目标类，不建议粗暴提高 conf（会掉召回）；优先从表征和数据入手。

## 5. 达到整体 mAP50 = 0.9 的推进优先级

1. **先修数据质量**（0 成本、收益最大）：清洗 Motorcycle 错标 → 复核漏标 → 统一 LGV/MGV、Van 的标注规范。
2. **换用无泄漏验证集**：`dataset/batch_12.v14i.merged12.yolov11/splits1.1/data_train_pool.yaml`（逐类 7:1:2、group 无泄漏）。用泄漏的旧 `data.yaml` 评出的 0.816 不可作为决策依据，也无法定位真实短板。
3. **救弱类**：LGV / Van / MGV / Motorcycle 决定 0.9 能否达成，按 §2、§3、§4 执行。
4. **训练配方**：优先用已 tuned 超参（`logs/best_hyperparameters.yaml`；参考 `experiments/train_merged12_best.py`：`lr0≈0.0114, box≈4.62, cls≈0.32, mosaic≈0.44, scale≈0.55`），并采用 `scripts/run_multistage.py` 的两阶段（full pool 预训练 → HQ 子集、mosaic off 微调）。
5. **分辨率/结构**：若小目标仍是瓶颈，上 960 输入 + P2 头。
6. **兜底方案**：若业务允许，按 README 的 v10 经验合并 LGV/MGV/HGV → Truck，可一次性消掉最大的类间混淆，整体 mAP50 提升明显。
