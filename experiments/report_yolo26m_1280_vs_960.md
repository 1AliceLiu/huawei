# 分析报告：yolo26m @1280 vs @960

**实验组**：`runs/detect/yolo26m_merged12_1280_20261016_0853`（yolo26m, imgsz=1280, batch=32）
**对照组**：`runs/detect/yolo26m_merged12_20261016_0315`（yolo26m, imgsz=960, batch=64）
**数据集**：`dataset/clean_part_batch_12.v8i.merged12.yolov11`（12 类）
**评测**：两个 `best.pt` 均在**当前清理后的 valid**（1895 图 / 10884 框）上重新评测

> 重要提示（混杂因素）：`0315` 训练时用的是**清理前的旧标签**，`0853` 训练时用的是**清理后的标签**。
> 所以下面的差距 = **分辨率(960→1280) + 标签清理** 两部分的共同结果，无法只归因于分辨率。
> 若要单独分离分辨率收益，需要补一组「清理后标签 + 960 + batch64」的对照。

## 3. 原因分析

**① 分辨率提升主要救"小/被压缩/需要细纹理"的类。**
提升最大的正是这几种：MGV +0.091、Container +0.056、LGV +0.049、Coach +0.043。
它们的共同点是**箱体/载重边界细小或被压缩**，960 下连成一片、1280 下才分得开。
Recall +0.055 而 Precision 几乎不变，也说明网络"多找到了原本漏掉的目标"，符合分辨率假设。

**② 大目标类反而略降（HGV -0.024、Van -0.017、Motorcycle -0.010）。**
这些框本来就大，分辨率不是瓶颈；小幅波动更可能来自 **batch 64→32 改变了优化动态**（有效 batch 变小、梯度噪声变大），或 LGV/MGV/HGV 边界重排导致的虹吸。

**③ 标签清理的贡献无法忽略。**
0315 训练用的是旧标签（29 处重复框、20 处同框多标签、47 处类冲突、128 处近重复）。
这些矛盾标签会**同时制造误报和漏检**，清理后 AP 本就会上升。因此 +0.023 里有一块来自数据，
而不是纯分辨率。

**④ 模型更大 + 训练更久。**
0315 在 epoch 29 达到最优、60 轮早停；0853 在 epoch 63 最优、78 轮早停，
train/cls_loss 0.44→0.37、val/cls_loss 0.947→0.913。1280 下样本信息更多，模型学到更晚、更充分。

**结论**：分辨率是**正向但边际**的收益（整体 +0.023 mAP50，小目标类 +0.05~0.09），
且必须训练/评测同分辨率。想要 0.9，光靠分辨率远远不够。

## 4. 如何把平均 mAP50 提到 0.9

当前 0853：**mAP50 = 0.7748**，距 0.9 还差 **+0.125**。
拖后腿的六类（<0.82）：**LGV 0.50、Container 0.54、Van 0.64、MGV 0.71、Motorcycle 0.75、HGV 0.81**，
这六类平均仅 **0.660**；其余六类平均已 **0.890**。

> 关键判断：mAP 是**按类平均**，所以你必须把这 6 个"地板"抬起来。在 12 个细类上把它们同时抬到 ~0.85，
> 整体才可能到 0.9。**只调参不可能，必须动"分类体系 + 标注"这两件事。**

### 路线图（按性价比排序）

**第 1 步｜合并货车家族（最大杠杆）**
把 `LGV + MGV + HGV → Truck`。理由你们 README 已验证过：载重/涂装边界在监控视角下**视觉不可分**
（HGV↔MGV↔LGV 互相误判）。合并后这三个 0.50/0.71/0.81 的低分直接消失，换成高分的 Truck。
参考 merge8 经验，仅此一步通常能带来 **+0.06~0.10** 的整体 mAP50。

**第 2 步｜Container 用"可见证据"重标或并入 Truck**
Container 的判据（箱体条纹 + 后 6 轮）在压缩/远景姿态下不可见，属于**图像不可判**样本。
- 方案 A：仅在**条纹或后轮结构可见**时标 Container，其余改标 Truck/HGV；
- 方案 B：直接把 Container 并入 Truck，把"是否载箱"当属性。
这一步能显著抬 Container，并减少它与 HGV 的互相污染。预期 **+0.02~0.04**。

**第 3 步｜保留 1280 并污染 Van↔Private Car**
- 分辨率继续保持 1280（本实验已证 +0.02，且对小目标更友好）。
- Van 0.64 的 27% 是 Van↔PC 混淆，按同样思路：审 Van/PC 边界标注，补采"无窗货车/涂装 Van"样本。

**第 4 步｜开 `cls_pw`（未用过）**
在合并后的类别上设 `cls_pw≈0.3~0.5`，压主类、抬稀有类，通常再 **+0.01~0.03**，且成本极低。

**第 5 步｜模型与训练**
- 用 yolo26m 或更大；1280 下 batch 尽量大（可考虑 3 卡或升显存）。
- 训练到充分收敛（现在 78 轮早停，可放大 patience / 调 lr0）。

### 预期
| 步骤 | 预计 mAP50 |
|---|---|
| 现状（0853） | 0.775 |
| +合并 Truck | ~0.85 |
| +Container 重标/并入 | ~0.87 |
| +cls_pw + Van 治理 + 充分训练 | **~0.89–0.92** |

> 也就是说：**0.9 可达，但前提是合并类别 + 统一 Container 标注口径**，不是继续在 12 类上堆实验。
